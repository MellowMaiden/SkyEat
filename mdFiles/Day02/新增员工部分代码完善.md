# 一、401 问题记录

## 问题现象

第二天重新测试新增员工接口：

```http
POST /admin/employee
```

返回：

```http
401 Unauthorized
```

---

## 原因

项目里配置了 JWT 拦截器：

```java
/*registry.addInterceptor(jwtTokenAdminInterceptor)
        .addPathPatterns("/admin/**")
        .excludePathPatterns("/admin/employee/login");
```

表示：

除了登录接口：

```http
/admin/employee/login
```

其他所有：

```http
/admin/**
```

请求都必须带 token。

---

新增员工接口：

```http
POST /admin/employee
```

也属于：

```http
/admin/**
```

所以必须带 token。

---

请求头名字来自配置：

```yaml
sky:
  jwt:
    admin-token-name: token
```

所以请求头必须这样传：

```http
token: xxxxxxxxxxxxxx
```

---

## 为什么昨天能用今天不行？

因为 token 有过期时间：

```yaml
admin-ttl: 7200000
```

即：

```text
7200000 ms = 2小时
```

昨天登录拿到的 token，今天已经过期。

所以被拦截器拦住，返回：

```http
401
```

---

## 解决方法

重新调用登录接口：

```http
POST /admin/employee/login
```

请求：

```json
{
  "username":"admin",
  "password":"123456"
}
```

复制返回的新 token。

然后在 Knife4j 请求头添加：

```http
token: 新token
```

再调用新增员工接口即可。

# 二、ThreadLocal 获取当前用户 ID

---

## 最初代码

之前写的是：

```java
//employee.setCreateUser(10L);
//employee.setUpdateUser(10L);
```

问题：

```text
10L 是写死的
```

谁登录都是 10，不合理。

---

## 目标

实现：

```text
谁登录操作，就记录谁的 id
```

例如：

```text
admin 登录 -> create_user = admin.id
tom 登录 -> create_user = tom.id
```

---

# 三、实现流程

## 1）登录成功生成 JWT

用户登录成功后生成 token：

```text
token
```

token 中保存：

```json
{
  "empId":10
}
```

---

## 2）拦截器解析 token

在：

```java
//JwtTokenAdminInterceptor
```

中：

```java
//Claims claims = JwtUtil.parseJWT(...);
```

拿到：

```java
//Long empId
```

---

## 3）存入 BaseContext

新增代码：

```java
//BaseContext.setCurrentId(empId);
```

把当前登录用户 id 保存起来。

---

## 4）Service 层取出使用

在新增员工时：

```java
//employee.setCreateUser(BaseContext.getCurrentId());
//employee.setUpdateUser(BaseContext.getCurrentId());
```

从 BaseContext 取出当前用户 id，写入数据库。

---

# 四、核心链路总结

```text
用户登录
↓
生成 JWT token
↓
token 中保存 empId
↓
发送请求携带 token
↓
拦截器解析 token
↓
取出 empId
↓
BaseContext.setCurrentId(empId)
↓
Service 调用 BaseContext.getCurrentId()
↓
保存 create_user / update_user
```

# 五、重点记忆

## JWT 是什么？

用于保存登录信息。

例如：

```text
当前登录用户 id
```

---

## Interceptor 做什么？

拦截请求、校验 token、解析 token。

---

## BaseContext 做什么？

保存当前登录用户 id，供后续业务代码使用。

---

## ThreadLocal 做什么？

BaseContext 底层使用 ThreadLocal。

作用：

```text
给当前线程单独存一份数据
```

这样每个请求都能拿到自己的用户 id，不会互相影响。
